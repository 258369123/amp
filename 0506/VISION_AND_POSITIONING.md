# 🎯 AMP 平台定位和愿景

## 核心定位

**AMP (AI-driven Autonomous Penetration Testing Platform)** 是一个 **AI 驱动的自主渗透测试平台**，旨在将 Claude Code 的智能能力与渗透测试工具深度集成，实现智能化、自动化的网络安全测试。

---

## 🎯 三大核心定位

### 1. AI 助手的"手和眼"

**问题**: Claude Code 很聪明，但缺少操作工具
- Claude 可以分析、决策、规划
- 但无法直接操作网络、创建隧道、执行命令

**AMP 的角色**: 成为 Claude 的执行层
- 提供 17 个 MCP 工具
- Claude 通过工具操作真实网络环境
- 将 AI 的智能转化为实际行动

**类比**: 
- Claude = 大脑（思考、决策）
- AMP = 手和眼（执行、观察）

---

### 2. 渗透测试的智能编排器

**传统方式**: 手动操作各种工具
```bash
# 手动创建隧道
chisel client 192.168.1.100:8080

# 手动创建 Shell
nc -lvp 4444

# 手动记录和分析
# ...
```

**AMP 方式**: AI 驱动的自动化
```
> 帮我建立到内网 10.0.0.50 的访问路径

Claude 会自动：
1. 分析网络拓扑
2. 规划隧道链
3. 创建必要的隧道
4. 验证连接性
5. 记录所有操作
```

**价值**: 
- 减少重复劳动
- 避免人为错误
- 提高测试效率
- 自动记录过程

---

### 3. 渗透测试的知识库和记忆系统

**问题**: 渗透测试过程复杂，容易遗忘
- 执行了哪些命令？
- 哪些路径可行？
- 之前尝试过什么？

**AMP 的解决方案**: 智能上下文管理
- **向量搜索**: 找到相似的历史操作
- **动态提示**: 根据当前情况推荐下一步
- **渐进式披露**: 只显示相关信息
- **操作历史**: 完整记录所有操作

**场景**:
```
> 我之前是怎么访问这个内网的？

AMP 会：
1. 搜索相关操作历史
2. 找到之前的隧道配置
3. 推荐相同或类似的方法
```

## 🎨 设计理念

### 1. AI-First（AI 优先）

**不是**: 传统工具 + AI 包装  
**而是**: 从 AI 角度设计的工具

- MCP 协议原生支持
- 自然语言交互
- 上下文感知
- 智能决策支持

### 2. Human-in-the-Loop（人在回路中）

**不是**: 完全自动化（危险）  
**而是**: AI 辅助人类决策

- AI 提供建议和执行
- 人类做最终决策
- 关键操作需要确认
- 保持人类控制权

### 3. Transparency（透明性）

**不是**: 黑盒操作  
**而是**: 完全可见和可控

- Web UI 实时可视化
- 所有操作可追溯
- 网络拓扑清晰展示
- 操作历史完整记录

## 🎯 使用场景

### 场景 1: 内网渗透

**传统方式**:
```bash
# 1. 手动创建第一层隧道
chisel client ...

# 2. 手动创建第二层隧道
ssh -L ...

# 3. 手动记录配置
# ...

# 4. 手动测试连接
# ...
```

**AMP 方式**:
```
> 帮我建立到 10.0.0.50 的访问路径，中间需要经过 DMZ

Claude 自动完成所有步骤，并在 Web UI 中可视化展示
```

### 场景 2: 权限提升

**传统方式**:
```bash

...

# 2. 手动搜索提权方法
# Google 搜索...

# 3. 手动尝试各种方法
# ...
```

**AMP 方式**:
```
> 分析当前 Shell 的提权可能性

Claude 会：
1. 自动执行枚举命令
2. 分析系统信息
3. 搜索相关历史操作
4. 推荐可行的提权方法
```
